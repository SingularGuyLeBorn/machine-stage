## 一、这些文档是什么

每份装备文档**自包含四层**，实现时四层都不能漏：

1. **零件树** —— 零件级粒度。拆到每个液压缸 / 每根管 / 每块板 / 每圈螺栓，不许总成级糊弄。
   每个零件有 `partId`，可定位、可拆解、可检测、可动画。
2. **机构运动** —— 每个可动件能演示运动学。阻尼感总则：慢启动 → 加速 → 减速 → 过冲回弹。
3. **受击战损** —— 分级三态：掉漆 → 凹陷 → 穿孔 → 破碎。破碎是**不规则撕裂口**，
   带翻卷 / 裂纹 / 碟形变形，不是规整圆圈。
4. **质感层** —— 材质 / 涂装身份 / 做旧 / 战场痕迹。漏了这层就是"新车不像战车"。

方法论总纲：**零件化 + 自内向外**。先内脏后外壳；装配器按注册表声明（几何 / 材质 / 配合 / 实例）
生成整棵树。

## 四、纪律红线（实现时逐条对照）

- 重复件必须**实例化**（同一 partId 多实例，不复制几何）
- **零穿模、零悬空**（靠自动化检测，不靠肉眼；白名单要逐个复核，别误豁免真穿透）
- **零件级粒度**，不许总成级
- **质感层别漏**
- **人机工程校验**：人够得着吗、手转得开吗（机枪曾放在前人够不着的位置）
- **commit 带原因**，不留积压
- `tsc` / `vitest` 全绿，**测试只增不减**
- **存疑即报**，不猜着做
- 只在自己 worktree 内改动
- **文档提交进 git**（这份索引的存在就是为了这条）
