## 模型与发布

实际装配为 **2,578 件、28,484,688 个三角面**。没有对展示网格减面。局部实体配合修改为 610 件，目标间隙沿用 0.22 mm，并在 float32 导出精度下核对残余相交。

展示台缓存与实际导出网格的顶点、法线、UV、索引及变换逐字节一致。55 个压缩块合计 781,170,962 字节；983 份独立网格，1,595 处重复几何共享检查通过。离线解压约 5.30 秒、装配约 0.93 秒，300 次拾取检查和独立缩放隔离检查通过。这些数值来自本机离线检查，不代表浏览器冷启动时间或帧率。

加工器改为有界实体缓存和逐件检查点，已完成零件按源网格及配合件内容复用；加工器及辅助文件变化会使检查点失效。Blender 共享完全相同和镜像还原后相同的网格。渲染使用 CUDA，沿用原有灯光、相机、材质和 40 次采样。

## 检查范围与剩余问题

- 50 项相关测试通过：确认体态、三片腰甲可见性、L1–L5 装配碰撞、单个有支撑的装配组件、贯穿孔、活塞插接、分件拆装及缩放均通过。
- 独立实体检查在实际 float32 导出上发现超过 10⁻¹² m³ 的相交为零；没有使用碰撞豁免。类型检查、所改文件 ESLint 和生产构建通过。
- 全部 2,578 件网格闭合；受保护的连杆、弹簧和安装座连续性检查无失败。
- 所有材料实体的连通检查由基线 35 件提示降至 28 件。27 件沿用基线中的颈侧、颅内、下颌、部分内衬等问题；下腰背耳板新增两个微小碎片，合计约 0.0096 mm³。因此“每一个命名零件都只有一个材料实体”仍未全过，不能把闭合检查等同于这一项通过。
- 切除量超过 25% 的提示有 22 件，其中 14 件沿用基线提示、8 件新进入该范围。最大为拇指根护甲约 41.66%。这些值仍保留在审查记录中，未验证制造强度或机械承载。
- 浏览器工具此前未允许观察展示台，本轮网页实际加载、帧率及交互没有验收。发布缓存和生产构建已更新。
- 全仓 `npm run lint` 会扫描本地 `qa-out` 草稿、回退副本和 `vendor`，有 117 条错误、285 条警告；本轮修改的 TypeScript 文件 ESLint 无错误。生产构建仍有大包体积提示。

最终检测数值和新旧问题逐件对照见 `qa-out/armor-verification.json`；实际执行日志以 `qa-out/armor-*.log` 为准。

## 查看与重建

四视图与近景在 `qa-out/hmt-*.png`。`qa-out/armor-before` 是从体态确认版网格、使用同一套灯光和相机重新渲染的修改前四视图。对比在 `qa-out/hmt-armor-comparison-{front,side,three-quarter,back,overview}.png`。

模型为 `qa-out/hmt-current.blend`、`qa-out/hmt-mesh.json` 与 `qa-out/hmt-mesh.bin`。源文件与全部交付文件的绝对路径列在 `qa-out/armor-delivery-manifest.json`。

```text
npx tsx scripts/export-hmt.ts --raw
python -X utf8 scripts/machine-hmt.py
npx tsx scripts/export-hmt.ts --runtime
npx vitest run src/three/parts/models/hmt --maxWorkers=1
python -X utf8 qa-out/check-manifold.py
python -X utf8 qa-out/solid-overlaps.py
npx tsx scripts/verify-hmt-runtime.ts
blender -b -t 6 --python-exit-code 1 --python scripts/render-hmt.py -- --gpu
python -X utf8 qa-out/make-redline-comparisons.py qa-out/armor-before hmt-armor-comparison
npm run build
```

使用 `--batch-size=200` 时，退出码 75 表示一批已保存，可再次运行同一加工命令；其他非零退出码表示失败。大型模型和发布二进制保存在本机，依照现有忽略规则不纳入 Git，可由生成源重建。
