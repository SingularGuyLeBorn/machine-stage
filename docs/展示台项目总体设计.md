## 0. 一句话项目

一个纯前端 3D 军工装备展示台：**左栏角色库 / 中间 3D 视口 / 右栏动作面板**；所有模型**纯代码程序化生成**（不加载外部网格），按**零件化注册表**装配，按**自内向外**顺序构建，每个零件有唯一 ID，穿模可定位到实例。

## 1. 设计哲学：自内向外（Inside-Out）

旧方式（禁止）：先放样一个外壳 → 发现里面空 → 往里塞零件 → 穿模了 → 在几千行代码里摸黑找。

新方式（必须）：**从"心脏"开始造，验证一层再包一层**。

```
L1 核心机构   发动机本体 / 枪机 / 炮闩         → 先让心脏动起来
L2 传动支撑   变速箱 / 活塞连杆 / 承力骨架      → 让力传出去
L3 内衬内饰   座舱 / 仪表 / 座椅 / 弹药架       → 人待的地方
L4 外壳蒙皮   装甲板 / 机身蒙皮 / 舱盖          → 包裹起来
L5 表面与附件 涂装 / 磨损 / 工具 / 标识          → 最后化妆
```

**每层都是可见的里程碑**：L1 完成时，你就能看到发动机转子转、枪机往复、炮闩开闭——带动画、有穿模检测报告。不是等全做完才发现里面错了。

### 天然副产品：构建进度回放

因为每个零件在注册表里带 `build_layer`（L1–L5）与 `build_order` 字段，查看器提供一个**构建进度滑杆**：拖动 0%→100%，模型从发动机一步步组装成整车——这是本展示台的**杀手级特性**，实现成本为零（就是按字段过滤显示零件）。

## 2. UI 布局

```
┌────────────┬──────────────────────────┬────────────┐
│ 左栏：角色库  │        中栏：3D 视口        │ 右栏：动作  │
│            │                          │            │
│ 模型列表     │   轨道/剖切/爆炸图         │ 动作按钮    │
│ 零件树       │   ★构建进度滑杆★          │ 状态机图    │
│  (按总成折叠) │   ★穿模报告浮层★          │ 参数面板    │
└────────────┴──────────────────────────┴────────────┘
```

- **左栏**：模型列表（卡片）+ 当前模型的零件树（按 assembly 折叠，点零件高亮聚焦）。
- **中栏**：3D 视口 + 底部**构建进度滑杆**（拖到哪一层就只显示哪一层及以内的零件）+ 穿模报告浮层（点击报告项，相机飞到穿透点并高亮两个零件）。
- **右栏**：动作按钮（按"机构 / 展示 / 射击"分组）、状态机图（当前状态高亮）、参数面板（改参数实时重建）。

## 3. 技术栈与目录

沿用现有栈（已装好，勿换）：**Vite + React 19 + TypeScript + Three.js 0.170 + @react-three/fiber + @react-three/drei + Zustand**。运行：`npm run dev`。

新增目录约定：

```
src/three/parts/
  registry/          # 每个模型一个 *.parts.json（或 .ts 常量表）
  assembler/         # 注册表 → 场景树的装配器
  solver/            # 穿模检测器（静态 + 动画扫掠）
  kernel/            # 几何内核（沿用并扩展 detailKit.ts）
src/three/code/      # 模型生成器（每个模型一个文件，入口只做：读表 → 装配 → 出动画）
public/assets/environment/  # HDR 环境（已有）
```

**纪律**：模型生成器里**禁止出现匿名的 `put(box, x, y, z)` 流水账**；一切零件来自注册表，一切坐标来自 `constants` 或 `mate` 派生。

## 4. 零件化数据格式（基线摘要，全文见《零件化建模框架.md》）

零件 ID：`model.assembly.part[index]`
- 双侧件先左后右：履带 `[0..95]` 左 / `[96..191]` 右
- 可动件必须声明所属骨骼节点 `node`（动画只驱动节点）

注册表条目（字段允许扩展，不许改语义）：

```json
{
  "id": "tiger.track.link",
  "name_cn": "履带板", "name_en": "track link",
  "assembly": "track",
  "build_layer": 2, "build_order": 210,
  "instances": 192, "indexed": true,
  "mate": { "type": "path", "to": "TRACK_PATH" },
  "material": "track_cast"
}
```

穿模报告（solver 输出，QA 浮层消费）：

```json
{ "a": "tiger.track.link[42]", "b": "tiger.suspension.roadwheel[7]",
  "depth_mm": 3.2, "point": [1.42, 0.48, 1.15],
  "hint": "导向齿与轮缘重叠：检查 TRACK_X 与 LANES 间隙" }
```

## 5. 自内向外构建法（核心交付逻辑）

### 5.1 五层定义

| 层 | 内容（以虎式为例） | 本层验证 |
|----|-------------------|---------|
| **L1 核心机构** | HL230 发动机（缸体/曲轴/活塞/风扇）、88 炮炮闩+驻退复进机 | 曲轴转动动画；炮闩开闭；层内穿模报告为空 |
| **L2 传动支撑** | 变速箱、传动轴、扭杆悬挂、摆臂、履带驱动 | 履带滚动路径数学验证；悬挂行程动画 |
| **L3 内衬内饰** | 驾驶舱（座椅/仪表/方向盘）、战斗舱（弹药架/手轮/吊篮）、象牙白内衬 | 开盖视角检查；吊篮-座圈旋转扫掠检测 |
| **L4 外壳蒙皮** | 首上/侧面/车尾装甲板、炮塔壳体、翼子板、舱盖 | 全车静态穿模检测；外壳与内衬间隙检查 |
| **L5 表面与附件** | 涂装/迷彩、焊缝、铆钉、工具、备用履带、贴花 | 视觉验收（见真实感指南） |

### 5.2 里程碑顺序（四个首发模型通用）

1. **M-A：框架底座**。装配器 + 穿模检测器 + 构建滑杆。验收：能加载一张只有 3 个零件的测试表并输出实例级报告。
2. **M-B：第一个 L1**。虎式 HL230 发动机（V12 缸体 + 曲轴 + 活塞 + 双散热风扇 + 空滤）。验收：曲轴-活塞-风扇联动动画 + 层内零穿模。
3. **M-C：虎式全五层**。按 L1→L5 顺序推进，每层过验收才进下一层。
4. **M-D：M2HB 重机枪**（核心层 = 管退式自动机：枪管+枪机+加速器）。
5. **M-E：AK-47**（核心层 = 导气式自动机：活塞+枪机框+枪机）。
6. **M-F：歼-20**（核心层 = 主承力框 + 弹舱滑轨机构；发动机复用涡扇总成思路）。

**为什么这个顺序**：虎式零件最多但资料最全（Tigerfibel）；M2HB/AK-47 零件少、机构经典，验证框架速度最快；J-20 最后因为它的大曲面机身对几何内核要求最高。

### 5.3 每层"完成"的判据（不满足不进下一层）

- [ ] 本层零件全部在注册表，无匿名 mesh
- [ ] 本层穿模检测报告为空（实例级）
- [ ] 本层机构动画播放无穿模（≥30fps 采样）
- [ ] 构建滑杆拖到本层时，模型"立得住"（能讲清楚这是什么）

## 6. 视觉与渲染基线（验收底线，细节可发挥）

- 真实尺寸建模（米制），顶部注释块列出关键尺寸及来源（MACHINE_STYLE 第 1 节）。
- 材质：金属/漆面/橡胶/玻璃并排可辨；大面积涂装必须带板缝+铆钉+油渍三联贴图（`detailKit.panelTextures`）。
- 几何红线：主曲面必须放样/Lathe/圆角挤出；**禁止裸大盒体**；板件分布**不均匀**（口盖周围密、大蒙皮稀——警惕"密度陷阱"，见规格书 3.13.8）。
- 穿模零容忍（一票否决，见规格书 15.1）。
- 后处理：SSAO + ACES 色调映射必须开。

## 7. 发挥余地清单

**不许动（动了必跑偏）**：
- 三栏布局与构建滑杆的存在
- 零件 ID 规范、注册表语义、穿模报告格式
- 自内向外的层定义与里程碑判据
- 真实尺寸、米制、单一真值源常量

**自由发挥**：
- 装配器/检测器的具体实现方式（几何相交用 BVH 还是其他，随你）
- 每个零件的具体几何细节（在红线内尽量做真）
- 材质贴图的具体配方（在视觉基线内）
- 状态机面板、零件树 UI 的具体样式
- 动作/动画的编排（机构时序必须符合手册，美学节奏随你）
- 新模型选题（首批四个之后，规格书里有 21 型清单可选）

**主动回报**：遇到规格冲突、资料矛盾、性能瓶颈，在 `docs/PROGRESS.md` 追加一条"问题-决策"记录，不要静默绕开。

## 9. 参考资料（零件命名与机构时序）
