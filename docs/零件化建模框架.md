# 零件化建模框架（Part-Based Procedural Modeling）

> 适用对象：fight-stage 全部纯代码程序化模型（CodeCharacter），首批重构：**虎式坦克、M2HB 重机枪、AK-47、歼-20**。
> 本文档与 `MACHINE_STYLE.md` 的关系：MACHINE_STYLE 定"风格标准"，本文档定"装配架构"——**让每个零件都有身份，让穿模可以定位到实例**。

---

## 1. 为什么必须零件化

现有代码（tigerTank.ts 4473 行、apache.ts 3819 行）是**流水账式构建**：零件在几千行代码里按顺序 `put()`，坐标靠手算字面量。后果：

1. **穿模无法定位**：发现"履带和轮子穿了"，只能肉眼在几千行里找——无法回答"第几节履带和第几个轮子、穿在哪"。
2. **改一个动全身**：没有单一真值源，改炮塔座圈半径，炮塔、吊篮、指挥塔各自为政。
3. **无法做碰撞检测**：检测器拿到的只是一堆匿名 mesh，报告"part123 与 part456 相交"毫无意义。
4. **无法复用**：履带板逻辑焊死在 tigerTank 里，88 炮的履带无法借用。

零件化后：每个零件有**唯一语义 ID**，重复件有**实例索引**，穿模报告直接输出 `tiger.track.link[42] ↔ tiger.suspension.roadwheel[7]`，debug 一步到位。

---

## 2. 核心概念

| 概念 | 定义 | 示例 |
|------|------|------|
| **Part（零件）** | 最小装配单元：1 份几何 + 1 种材质 + 1 个挂载点 | 炮盾、履带板、枪机 |
| **Instance（实例）** | 同一零件的重复安装，带数组索引 | `track.link[42]` |
| **Assembly（总成）** | 零件的分组容器，对应真实装配层级 | `turret`（炮塔总成） |
| **Node（骨骼节点）** | 可动件的动画挂载点，零件挂在节点上随动 | `GunCradle`（俯仰架） |
| **Registry（注册表）** | 一个模型的全部零件声明（JSON），代码按表组装 | `tiger.parts.json` |
| **Mate（配合）** | 零件间的关系声明：贴合/同轴/距离/角度 | `mantlet ↔ cradle: coaxial` |

**铁律：零件的位置由 Mate 关系 + 单一真值源常量派生，禁止手写孤立字面量坐标。**

---

## 3. 命名规范

```
<model>.<assembly>.<part>[<index>]

model     小写机型：tiger / m2hb / ak47 / j20
assembly  小写总成：hull / turret / receiver / wing
part      小写零件：mantlet / track_link / bolt
index     实例索引（仅重复件）：[0]..[n-1]
```

**实例索引分配规则（必须全项目统一）：**

- 双侧件：先左后右。如 `track.link[0..95]` 左侧、`[96..191]` 右侧。
- 环列件（螺栓圈）：从 +Z 方向起，逆时针编号。
- 行列件（铆钉列）：从机头向机尾编号。
- 同侧多排件（交错负重轮）：先轴序（前→后）后排序（内→外）：`roadwheel[0..23]` 左 = 轴 0..7 × 排 0..2。

**节点命名与零件 ID 对齐**：节点 `Turret` 下挂 `tiger.turret.*` 全部零件；动画轨道只引用节点名，不直接引用零件。

## 4. 注册表格式（tiger.parts.json 节选）

```json
{
  "model": "tiger",
  "constants": {
    "HULL_FRONT": 3.1, "DECK_Y": 2.02, "TRACK_X": 1.4175, "WHEEL_R": 0.4
  },
  "assemblies": ["hull", "turret", "gun", "suspension", "track", "engine"],
  "parts": [
    {
      "id": "tiger.hull.glacis_upper",
      "name_cn": "首上装甲板",
      "name_en": "glacis plate, upper",
      "assembly": "hull",
      "geometry": { "type": "plate", "w": 3.3, "h": 1.0, "t": 0.1 },
      "material": "armor_rolled",
      "mate": { "type": "flush", "to": "tiger.hull.tub", "offset": [0, 1.0, "HULL_FRONT-0.05"] }
    },
    {
      "id": "tiger.track.link",
      "name_cn": "履带板",
      "name_en": "track link (Kgs 63/725/130)",
      "assembly": "track",
      "geometry": { "type": "track_link", "w": 0.725, "pitch_from": "TRACK_PATH_LEN/96" },
      "material": "track_cast",
      "instances": 192,
      "indexed": true
    },
    {
      "id": "tiger.suspension.roadwheel",
      "name_cn": "负重轮",
      "name_en": "roadwheel, 800mm, rubber-rimmed",
      "assembly": "suspension",
      "geometry": { "type": "lathe_dish", "r": 0.4 },
      "material": "wheel_painted_rubber",
      "instances": 48,
      "indexed": true,
      "node": "Suspension"
    }
  ]
}
```

- `constants`：**单一真值源**。所有零件位置由它派生；支持字符串表达式引用（`"HULL_FRONT-0.05"`）。
- `mate`：装配关系——`flush`（面贴合）/ `coaxial`（同轴）/ `distance` / `angle`。改常量时配合关系自动传播。
- `node`：所属骨骼节点（可动件必填）。

---

## 5. 骨骼化约定

- 每个可动机构对应一个命名 Node：`Turret`（回转）、`GunCradle`（俯仰）、`RecoilCarrier`（后坐）、`TrackScrollL/R`（履带滚动）、`SprocketL/R`、`IdlerL/R`。
- 可动零件**必须**挂在对应 Node 下，静止件挂静态 Node。
- 动画剪辑驱动 Node（不驱动单个零件），零件随 Node 联动——这保证"炮塔转动时，炮盾、指挥塔、储物箱作为整体运动，内部无相对穿模"。
- Node 层级 = 装配层级：`root → Vehicle → Turret → GunCradle → RecoilCarrier → BarrelGroup`。

---

## 6. 穿模检测与报告格式

**三级检测：**

1. **静态装配检测**：构建完成后，所有零件对做包围盒粗检 → 相交对做三角形精检。
2. **运动扫掠检测**：每条动画剪辑按 ≥30fps 采样，运动 Node 下零件 vs 静止件逐帧检查。
3. **参数扫描检测**：参数面板 min~max 步进扫描重建，重复 1、2。

**报告格式（可定位到实例）：**

```json
{
  "type": "clipping",
  "phase": "static | animation | param_scan",
  "a": "tiger.track.link[42]",
  "b": "tiger.suspension.roadwheel[7]",
  "depth_mm": 3.2,
  "point": [1.4175, 0.48, 1.15],
  "frame": null,
  "severity": "error",
  "hint": "履带板导向齿与负重轮缘重叠：检查 TRACK_X 与 LANES[3] 的横向间隙（应 ≥ 0.035）"
}
```

- `a`/`b` 必须是**注册表 ID + 实例索引**，禁止匿名 mesh 名。
- `hint` 由检测器根据零件的 Mate 声明自动生成——指到该改哪个常量。

## 9. 迁移策略（流水账 → 零件化）

现有 tigerTank.ts 不是推倒重来，而是**按以下顺序抽丝**：

1. **先抽常量**：所有字面量坐标收进 `constants`（已完成大半：文件顶部已有真实尺寸常量区）。
2. **再抽零件**：把 `put()` 调用按总成分组，每组生成注册表条目；几何生成函数与挂载信息分离。
3. **实例化重复件**：履带/负重轮/螺栓圈改为"1 份几何 + N 个实例矩阵"，索引按第 3 节规则分配。
4. **接入检测**：注册表 → 装配器 → 静态穿模检测自动跑；报告按第 6 节格式输出到 QA 面板。
5. **验收对齐**：以规格书 15.1 穿模一票否决 + 3.13 真实感标准验收。

**新模型（M2HB / AK-47 / J-20）直接按注册表起步，禁止再写流水账。**

## 10. 验收 checklist（本框架落地判据）

- [ ] 每个模型有独立 `*.parts.json`，零件数 ≥ MACHINE_STYLE 要求的 15–40 个命名零件。
- [ ] 每个零件有唯一 ID + `name_cn` + `name_en`（手册原名）。
