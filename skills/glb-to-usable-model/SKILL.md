# 从 GLB 到真正可用的模型

交付可检查、可复现、可装配、可运行的资产。**几何合格、视觉合格、运动合格是三份独立验收，不能相互替代。** 不承诺从单张照片恢复准确三维尺寸，不把闭合网格等同于可打印或可加工产品。

## 开工与范围

先确认用途：展示、可动分件、碰撞模型还是制造模型。上下文足够时直接执行。复述成功标准、保留项与可修改项；不要把某次项目的四分体、金属色、回弹或零间隙当成所有任务的默认要求。

保留原 GLB、材质与参考，记录哈希。找清实际分支、运行服务和构建目录，读该仓库适用规则。已确认模块先冻结，修改接口时检查配对侧。

## 路线与阅读顺序

1. 资产体检、参考读形、坐标与语义归组：读 [workflow.md](references/workflow.md) 的 1–6。
2. 闭合、布尔、接口与外观保真：继续读该文 7–12。初次先完成一对平整闭合截面，成熟资产不要无故退回重做。
3. 动画、天线、电弧与验收：读 [motion-and-qa.md](references/motion-and-qa.md)。检查实际播放姿态，不另造测试轨迹。
4. 命令、数据格式、依赖与脚本边界：读 [scripts.md](references/scripts.md)。不要凭函数名猜用法。
5. 实际反例：在相关环节读 [pitfalls.md](references/pitfalls.md)，尤其是扫掠空间变护甲、测试全绿但外形不对、源贴图不存在。
6. 原型转成品、布尔后的属性恢复、成品冷加载与完整案例：读 [production-and-case.md](references/production-and-case.md)。其中的数值是案例数据，不是所有项目的默认参数。

## 必须保留的不变量

- 源节点、骨骼权重、连通域和参考共同决定归属。不能用单一高度把整条手臂或髋鼓切断。
- UV/法线接缝不能因拓扑焊接抹掉。分析网格与渲染网格可分开，来源映射必须保留。
- 配对面由同一模具、一次 split 或互补布尔生成，不能分别近似雕刻。
- 运动避让体是空间，不是实体护甲。填实体必须有真实结构或参考依据。
- 要求闭合的分件必须检查实际导出精度下的边、绕序、体积与连通性；节点树分组不能证明连通实体。
- 不静默丢弃负体积壳、碎片或大孔，先判断内腔、绕序、缺面或数值碎屑。
- 外形相似度用真实渲染与参考对照；测试数量和体积守恒不证明造型像。
- 新附属件有真实安装点和运动空间；只豁免明确的构造接触，不豁免主体穿插。
- 资产、算法和预览必须同版。静态 dist 服务需要重新构建并由开发者载入验证。

## 工具选择

优先复用仓库：Blender 做导入、局部修复和渲染，manifold3d 做已闭合实体布尔，Three.js/BVH 做实际运行定位、探针和视觉检查。不要默认全局体素重建。

附带 `split_plane.py` **明确丢弃视觉属性，只是几何原型**，必须显式 `--geometry-only`。它不能冒充保留原 GLB 外观的成品导出器；生产导出按 workflow 的逐角属性与来源映射方法实现。

## 交付

提供资产/应用改动、可重跑配置与脚本、验证结果及实际渲染。说明按参考重塑和保留源资产的区域。区分静态检查、动画采样和连续碰撞保证；未运行过的脚本不标为可用。
