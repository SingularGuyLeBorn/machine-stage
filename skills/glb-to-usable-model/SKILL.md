# 从 GLB 到可用模型：先理解关系，再选择做法

这个 skill 传递的是面对模型时的判断方式。金古桥是这些判断产生的案例，不是其他模型应该套用的形状。脚本负责回答可测量的问题，参考和使用目标决定什么值得测量、什么才算改对。

以下原则来自用户在本次合作中的持续纠正：**仔细看实物关系，别只把描述翻译成几何；外观、分件和运动要说得通；先把当前问题做扎实，保住已经认可的部分。** 这是对这段合作的提炼，不推定其他用户也喜欢同样的形状、材质或动画。新任务中的明确要求优先。

## 先理解“可用”在这次任务里指什么

同一个 GLB 可以是好看的展示壳，却不是可独立移动的分件；也可以四件都闭合，却根本不像参考。先从上下文确定：人要看它、拆它、驱动它，还是制造它？这会改变问题的优先级和验收依据。

开始编辑前，能用具体关系说明目标。例如：“拆开时腿部保有完整髋鼓，装回时腹盆下凸台进入腿部凹槽，大臂在胸甲旁仍然外露。”这比“修好分体”更能约束实现。同步说清当前要动的区域，以及用户已经认可的区域。信息足够就执行，不把实现选型交给用户。

制造还需要材料、壁厚、公差和加工方向。展示模型的零间隙、闭合或动画通过，都不能替代这些条件。

## 看参考，是为了回答一个结构问题

动手前实际打开相关图片，不只读文件名和用户的比喻。每张图只承担它看得清的事实：正面有利于判断外轮廓，侧面揭示厚度与后倾，背面揭示退层，分解图揭示部件归属。阴影、反光和透视不直接当作几何边界。

参考的优先级随问题变化。用户要求剧中外观时，用剧照判断眼带气质和颜色，玩具图可以辅助看接口，却不能反过来定义剧中材质；用户要复刻某款玩具时，那款玩具才是目标。不同版本、比例、姿态先分开，不拼出一个没有依据的混合形体。

区分三件事：图上直接看见的关系、由多视图相互支持的推断、因资料不足暂时作出的选择。把影响结果的假设说清，例如“背面尚不可见，暂沿原壳保留”。不要求每次写长报告，也不把低清照片里的亮纹数量说成精确测量。

## 把语言还原成关系，不把比喻当零件

“山峰”可能是在说中央高、两侧落；“肺部”可能是在说双瓣、上窄下展；“圆润”可能是在说连接处的过渡。先回图里确认这些关系，再选曲线、曲面或局部修复手段。不要一听“山峰”就叠山形板，一听“圆润”就加大胶囊。

建模时同时看实体和空处：哪里必须有材料承接，哪里要留出手臂、凹槽或运动空间？两个部件各自看着漂亮，并不意味着放在一起正确。胸甲盖住大臂时，问题可能在护甲占据了错误空间，继续加倒角不会解决。

用户纠正的对象可能是你的理解。收到“不是前后各一半，是双榫插进头部”时，应替换原接口假设，重新检查受影响的两侧；不要把双榫叠到已被否定的前后切割方案上。

## 先判断错误在哪一层，再决定改什么

| 看到的现象 | 先区分什么 | 能帮助作出选择的检查 |
|---|---|---|
| 分体残缺 | 源件缺面，还是完整零件被分给另一模块 | 对照源骨骼、连通域与彩色归组；看残缺对应部分在哪里 |
| 正面像、侧面怪 | 轮廓对但深度错，还是视角/光照造成错觉 | 对齐机位看灰模，检查侧背退层是否跟着整个壳走 |
| 接口贴不上 | 配对几何不互补，还是节点/坐标变换错 | 先在统一空间比较配对面，再查装配矩阵 |
| 闭合但不自然 | 连通材料放错位置，还是过渡曲率不好 | 看大臂等保护件的可见面积与必要空隙，别只看体积 |
| 玻璃像浮贴板 | 安装面、曲率、厚度，还是仅材质不对 | 侧视根部及背面距离；几何正确后再调反射和颜色 |
| 动画僵硬或卡住 | 空间路径、速度、顺序，还是接口释放方向 | 分别看轨迹、近距姿态与世界速度；定位首次违背关系的位置 |
| 页面看不到修改 | 产物未更新，还是实现无效 | 确认分支、服务目录、模型卡片与当前构建，别急着再改参数 |

表中是待验证的判断，不是“症状一出现就执行对应修复”的规则。先做能够区分原因的小检查；结果不支持原假设，就换解释。不要靠不断加厚、加圆、放宽容差，把问题暂时藏起来。

## 保真需要选择：该保留的保留，该重塑的重塑

原 GLB 提供已有外观和部件信息，但不天然拥有正确闭合与分体结构。已经像参考的大臂、铆钉、法线和 UV，应尽量保留；已经被用户指出不对的胸甲轮廓，应允许局部重塑。全盘保留和全盘重建都会错过这个区别。

分件归属由语义、源数据和参考共同确定。高度只能帮助定位，不能决定完整手臂或斜髋鼓属于谁。**部件保留在正确模块里、表面仍能看见、实体真正连通，是三个不同要求。** 分别验证，不能用“节点挂对了”或“源顶点还在体积内”替代它们。

附属件也是关系问题。天线应该从哪个机械中心出来，眼带应该顺着哪片头壳，根部缩回后有没有容纳空间，都比先画一根漂亮的杆更重要。

## 一对接口是一件事；已确认区域是一条边界

凸起和凹槽共同描述同一个接触边界。改变凸起的层次时，相关槽底和侧壁应由同一设计更新，避免两边各凭感觉雕刻。共用模具或一次 split 是落实这种关系的手段，不是所有模型必须使用的某个库。

“前后退层顺着外壳走”要求连续的三维壳体关系，不能仅靠正面轮廓挤出；“顶部有小平顶”要求有限面积，不是把尖顶稍微降低。先说清要保持的关系，再选择参数。

用户认可的胸甲、腹盆或动画成为当前基线。新改动只沿真实依赖传播：调整某一接触面需要同步配对侧，不等于可以重做整个相邻模块。若保持已认可结构与新要求确实冲突，拿具体冲突说明，不能暗中改坏后再让用户找出来。

## 小步推进，是为了消除不确定性

不知道切割能否闭合时，一对简单平面样件很有价值：它把几何能力与复杂造型暂时分开。接口已经成熟、只是眼带颜色不对时，再做平面切割没有价值。选择当前最能减少返工的一小块工作，而非从固定第一步重走流程。

每次改动前，给自己留下简短的决策依据：**看到了什么 → 当前解释是什么 → 用什么现象区分其他解释 → 这次改哪里 → 怎样知道有效。** 这是可核验的工作说明，不需要输出冗长的内心推演或机械填表。

例如：眼带侧面悬空，说明仅调绿色无效；先测安装面并重做贴壳背面；外表面若随原低面数网格出现折痕，再用平滑曲面表达玻璃；最后分别看贴合和反光。换模型时仍沿用这个判断关系，不复制本例坐标或拟合系数。

## 验证必须回答本次问题

几何、视觉、运动分别提供不同证据。要求闭合时，审计实际导出精度下的边、绕序、体积与连通性；用户说“不像”时，给当前产物的同类机位对照；修改接口或路径时，检查真实播放中的释放、接近和回弹。测试数量不能回答外形是否正确，截图也不能证明内部无孔。

采样无碰撞只证明采样姿态，不证明连续全程。构造接触豁免只用于已知零件对和有依据的范围。不能放宽阈值来让错误方案过关。

检查范围跟随改动依赖。一个局部玻璃修改，不需要顺手改分体动画；但应确认它跟随头部移动、目标引擎能显示新材质。静态预览读取 dist 时，由开发者构建并载入当前版本。发现自己看的是旧产物，先解决版本问题。

当当前要求的关系在相应视角成立、相关几何/运行检查通过、保留区域没有回退，就交付这一切片。新的审美偏好需要用户继续反馈，不靠无限微调或“完全还原”的保证收尾。

## 按需要读取实现资料

- 想理解上述判断如何从误判中形成：读 [decision-cases.md](references/decision-cases.md)。每例说明触发信号、取舍、结果和迁移边界。
- 已确定问题在资产、坐标、分件或接口：查 [workflow.md](references/workflow.md) 的相关主题；它是实现备查，不是必走的十二道工序。
- 问题在路径、速度、电弧或运行验证：查 [motion-and-qa.md](references/motion-and-qa.md)。其中逐件合体、放电和回弹只适用于需要这些效果的任务。
- 要挑一个能检验假设的脚本：读 [scripts.md](references/scripts.md)，先看它能回答什么、不能回答什么。
- 遇到相似失败现象：用 [pitfalls.md](references/pitfalls.md) 找线索，再验证原因，不按症状直接套修复。
- 需要属性恢复、生产导出和冷加载：读 [production-and-case.md](references/production-and-case.md)。案例数值不是通用阈值。

优先使用项目已有工具。Blender、实体布尔、Three.js/BVH 各有适用问题；不因拥有某个脚本就把问题改造成脚本能做的样子。附带 `split_plane.py` 明确丢弃视觉属性，只能验证几何原型，不能冒充保留外观的成品导出器。
