# 从原型到成品，以及金古桥案例

## 一、生产数据不能只剩 positions 和 triangles

附带脚本的几何原型能证明切分可行，但真实项目还需要视觉属性、节点和材质资源。建议在项目适配层为每个源 primitive 保留以下内容：

| 数据 | 用途 | 丢失后的典型问题 |
|---|---|---|
| object/node/primitive/triangle ID | 布尔结果回查来源 | 相邻表面串材质、硬边被抹平 |
| 原位置与逐角法线 | 细节与光照 | 折边变软、金属表面变塑料 |
| 所有实际使用的 UV 集 | baseColor、normal、occlusion 等采样 | 贴图漂移、接缝拉花 |
| 材质索引与完整材质定义 | 恢复分组和 PBR 参数 | 灰模冒充原外观 |
| 顶点色及颜色空间约定 | 无图像资产的颜色 | 颜色消失、曝光不对 |
| 图片数据及引用关系 | 完整资源打包 | 本机能看，别人加载失败 |
| skin/weights/morph/animation | 若交付仍需原骨架或表情 | 静态烘焙后误称可动画资产 |
| 源到统一空间及逆变换 | 分件后重新挂节点 | 装配漂移、尺度重复应用 |

如果目标是刚体分体动画，可以明确烘焙一个姿态后改用模块节点运动；这会改变原骨架动画能力，应在交付范围中说明。不要一边丢掉 skin，一边宣称“无损转换”。

## 二、布尔后的属性恢复

优先使用布尔库提供的面来源映射。没有来源映射时，给每个源 primitive 建 BVH，并在原面候选中检查距离、方向和材质边界。单纯找空间最近点容易把薄壳正面投到背面，或把榫槽内壁误认成外壳。

对输出三角的顶点及质心取样，先找所属源三角，再求重心坐标。源三角为 `a,b,c`，查询点为 `p`，令 `v0=b-a, v1=c-a, v2=p-a`：

```text
d00=dot(v0,v0), d01=dot(v0,v1), d11=dot(v1,v1)
d20=dot(v2,v0), d21=dot(v2,v1)
denom=d00*d11-d01*d01
beta =(d11*d20-d01*d21)/denom
gamma=(d00*d21-d01*d20)/denom
alpha=1-beta-gamma
```

先拒绝退化源三角、明显离面点或落在三角外的点。UV 和颜色可按权重线性插值；法线插值后归一化。若涉及变换，先统一空间再进行方向比较。硬边两侧即使位置相同，也应保留不同逐角法线和 UV；导出时允许拆成多个渲染顶点。

新切面没有原纹理来源，要赋独立材质和 UV。平面封盖可建立正交基 `u,v,n`，用 `dot(p,u), dot(p,v)` 生成 UV；阶梯或曲面封盖应按模具参数展开，避免把整块复杂面压到一条 UV 线上。新外壳如胸甲按参考重塑，也应标为新面，不能从附近旧表面盲目拉伸纹理。

材质分组按**输出三角的材质 ID**重建。输出索引顺序改变后，旧 groups 的 start/count 不能照抄。法线贴图所需切线要与最终 UV/法线一致；没有切线时，确认目标引擎支持按导数重建，否则生成切线。

在属性回传后再检查一次几何：为 UV 拆点本身不会改变实体，但错误索引、位置精度、镜像绕序会让闭合失效。拓扑审计按位置身份检查，视觉检查按实际渲染属性检查。

## 三、成品 GLB 或应用资产的落盘

### 输出 GLB

在一个独立后台 Blender 场景中，为每个模块建立 Mesh 和模块节点；用最后的三角、逐角 UV/法线、材质建立渲染数据。使用局部几何与节点变换时，必须保持 `world = moduleWorld × localVertex`。不要同时把世界变换烘焙进几何又挂回相同变换的父节点。

根据交付决定：保留分件节点、烘焙确定的刚体动画，或只交付静态模块。把实际使用的图像随 GLB 打包。不要复制分析 JSON 中的材质名字就认为完成了材质恢复；本技能的 Blender exporter 只保留分析所需属性和材质引用，不打包原纹理。

导出后必须做“冷加载”：开启新进程重新导入最终 GLB，检查模块数量、bounds、材质、纹理、世界坐标和闭合；再在目标引擎实际载入。源场景正确不证明导出器没改节点/坐标/切线。把最终 GLB 的哈希写入报告。

### 输出到现有 Three.js 应用

沿仓库已有注册表/几何构建器接入，不再建第二套隐藏模型。将每个实体、装饰和天线挂到正确模块；材质工厂要支持实际用到的 vertexColors、clearcoat 等参数。只在 geometry 上设置 color 而材质未启用 vertexColors，颜色不会出现。

模型生成、实际播放和测试统一引用同一份资产。若预览服务读取 dist，代码改动不会自动进入静态预览；完成构建后重新加载并确认面数/版本/关键形体已变化。最终截图必须来自当前产物，不能拿旧截图作证。

## 四、金古桥的实际教训与处理顺序

这个案例是已有 GLB 转为四个可动主体，并按实物照片修改分体接口。下面的数字是该案例的结果，不能作为别的资产阈值。

1. **先确认源资产事实。** 原 GLB 有一个 mesh、46 个节点，但没有嵌入图像。彩窗后续是参考重建，不是恢复一张不存在的贴图。通用脚本在烘焙网格上查到 568 条开放边、101 个面连通域；这说明源数据不能直接当四个实体布尔切割。
2. **避免把骨骼显示器算进资产。** Blender 导入产生一个骨骼 custom_shape 辅助 Icosphere。最初导出误计为第二个物体，后来按 pose bone 的 custom_shape 引用排除。不能一律排除所有名字叫 Icosphere 的物体，因为用户可能真的有这个零件。
3. **先保住手臂和髋鼓归属。** 原始骨骼与语义归组比按高度切可靠。主躯干才参与正式接口切割；双臂完整随头肩，髋鼓完整随腿。腿被分给腹部的残缺断面不能靠盖板掩盖。
4. **先平整截面，再正式模具。** 原型证明闭合与互补后，腹盆改成小平顶、宽弧肩、沿壳体前后退层。胸甲和腿的凹槽由同一模具配对；已确认的下部冻结，修改上身时不重新切一遍下部。
5. **发现“拓扑通过但大臂消失”。** 之前把运动扫掠区域分给头肩，造出了巨大的接触块。正确处理是让该空间留空，只留局部圆润护甲和必要连接。增加了“大臂源表面仍外露”的检查，不能只检查源顶点位于实体内部。
6. **胸甲先改轮廓，再改彩窗。** 参考是上窄下展的双瓣，中央下缘抬高。旧横条彩窗改为不规则厚黑边、青黄红云斑和细颗粒。新彩窗前后都沿胸甲曲率细分，避免低面数背板穿入曲面。
7. **连接桥也要检查运动。** 头部与肩根的小缝需要局部桥接，但新桥静态闭合后，在原动作中出现约 `5.7e-5` 的体积交集。沿真实释放方向加工局部槽，给桥留出该项目单位下的 1 mm 余量；双榫主接触面不放宽。这个间隙是项目选择，不是通用制造公差。
8. **不要只检查高精度中间体。** 共面布尔在 Float32 导出后曾产生一条四次使用的边；局部完全相切又让接触边界出现四分叉。解决局部共面/相切条件后重新审计，而不是把“边必须两次”改成允许四次。
9. **检查真实播放函数。** 从实际应用导出 242 个姿态，再对四主体逐对做实体交集。最终最大交集约 `1.5e-8`，低于该项目 `1e-7` 的体积判据。它证明所采样姿态通过，不证明连续所有时刻都通过。
10. **分别保存三种结果。** 几何报告、运动报告、正侧背实际渲染分别保留。用户仍可能指出轮廓不像；这时按图修改，不能拿“所有测试绿”反驳视觉问题。

## 五、阶段验收与避免返工

| 阶段 | 进入下一步前必须留下的产物 |
|---|---|
| 盘点 | 源哈希、资源清单、尺寸/轴向、实际参考 |
| 语义 | 每件归属、保护件、未知件处理结果、彩色归组图 |
| 结构原型 | 一对闭合截面、重组差集/交集报告 |
| 正式接口 | 共用模具、配对侧、释放方向、冻结区域 |
| 外观 | 同机位参考对照、保留与重塑区域、材质来源 |
| 附属件 | 安装点、轴心、根部嵌入量、伸缩全程 |
| 动画 | 真实路径、速度变化、阶段顺序、实际姿态碰撞报告 |
| 交付 | 冷加载结果、目标引擎运行、当前截图、复现命令 |

出现问题时退回产生问题的层，而不是全部重做：颜色不对查材质/颜色空间；臂面被盖查实体归属；接口卡住查模具与释放路径；导出才开边查精度与索引；预览没变化查产物版本。每次修改后只扩大与改动有关的验证范围，保留已确认区域。

不能保证以后永远不返工；能做到的是每阶段暴露错误、每次有可复现基线，并让后来的人知道哪些结论来自图片、哪些来自几何、哪些只是设计假设。
